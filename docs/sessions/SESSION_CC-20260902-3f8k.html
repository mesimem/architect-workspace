mcp/booking-desk: structured log notifications with per-invocation correlation ids

Complete
Date
2026-09-02
What changed
booking-desk now DECLARES the logging capability and emits structured notifications/message lines. Nine stable event names across three namespaces - tool.* for handler lifecycle, dependency.* for the two supplier boundaries (each with duration_ms), booking.* for domain outcomes - with one uuid4 correlation id per invocation stamped on every line. Payloads are always objects carrying event and correlation_id, never formatted sentences, and carry identifiers, counts and durations only; the idempotency_key appears as an 8-hex SHA-256 fingerprint and never in full. booking.py gained an optional emit(event, fields) callback so the domain layer can report the availability and payment boundaries without importing MCP. strict_arguments.declared_arguments now excludes the Context parameter.

initialize capabilities are now ['experimental','logging','prompts','resources','tools'] - logging was ABSENT before this change, confirmed against the pre-change server. All 5 business paths exercised over a real stdio client (confirmed, replay, unavailable inventory, payment declined, idempotency conflict), each with exactly 1 distinct correlation id. Caught-error path: tool.book_trip.failed with error_class: "TimeoutError", re-raised, isError: true. logging/setLevel filters for real - 5 lines at info, 1 line after setLevel("warning"). Secret audit over 11 captured payloads: raw idempotency key absent, every payload an object with event + correlation_id, value types limited to str/bool/float/None. Input schema unchanged (5 properties, no ctx); {"ctx": "x"} rejected; resources, prompt and tools/list all still pass. Harness was scratch under tmp/ and is not committed.
Notes
TWO CAVEATS, both documented in the code. (1) The MCP logging capability is DEPRECATED as of protocol 2026-07-28 (SEP-2577) and this SDK marks Context.log and every level helper with MCPDeprecationWarning. There is no non-deprecated replacement for log notifications, and at 2026-07-28+ delivery became a per-request opt-in, so a client must send io.modelcontextprotocol/logLevel in the request _meta or the server MUST NOT send - it fails SILENTLY, which is exactly the trap the capability declaration also guards. (2) server._lowlevel_server.add_request_handler is NOT public API; MCPServer exposes no supported hook for a logging/setLevel handler in mcp 2.1.0, and registering that handler is the only thing that makes the SDK declare the capability, so the alternative was advertising a capability we do not serve. Same provisional-API caveat as the existing server.middleware use in strict_arguments.py. ONE FIX NOT ASKED FOR BUT REQUIRED: declared_arguments reads the tool signature to build the strict-argument allowlist, so adding ctx to book_trip would have made ctx a client-passable argument name and reopened the hole that module exists to close - on the one tool that charges a client. It now excludes the Context parameter via the SDK's own find_context_parameter, so renaming the parameter cannot silently reintroduce the gap. Also recorded: the roots-enforcement work requested this session was NOT done, because an audit found zero filesystem access anywhere in mcp/ (no open(), no os/pathlib/io/shutil/glob imports in any of the four servers), so there was nothing to guard and a helper wired into nothing would have been a security control that protects nothing. User chose to stop at the audit.
